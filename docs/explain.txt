# 2. Humne ye architecture kyun use kiya?

Ek hi Python file mein sab kuch likhne ke bajay functionality ko modules mein divide kiya.

For example:

```python
# bad for large project

everything.py
```

Instead:

```text
utils.py              → general utilities
cli.py                → command line interface
loaders.py            → dataset loading
eda_reporter.py       → data analysis
logistic_regression.py → ML model
scraper.py            → web scraping
```

Ye **separation of concerns** hai.

Matlab:

> Ek file/module ka ek clear responsibility.

Ye real-world software engineering mein important concept hai.


Matlab `cli.py` actual calculation khud nahi kar raha.

It calls:

```python

```

from:

```python

```

Ye bhi good architecture hai.

# 10. Function ka `return` kaise kaam karta hai?

Ye bahut important hai.

Suppose:

```python
def square(x):
    return x * x
```

Agar:

```python
result = square(5)
```

toh internally:

```text
square(5)
   ↓
5 * 5
   ↓
25
   ↓
return 25
   ↓
result = 25
```

`return` ka matlab:

> Function apna result caller ko wapas de raha hai.

# 17. `.round(10)` kyun lagaya?

Yahan ek interesting Python concept mila.

Mathematically:

```text
0.4² = 0.16
```

But computer floating-point representation ke wajah se Python internally kabhi:

```text
0.16000000000000003
```

produce kar sakta hai.

Isliye:

```python
.round(10)
```

use kiya.

# 27. Pehle return mein kya galti thi?

Old code:

```python
return {
    acc,
    report,
    conf_matrics
}
```

Ye dictionary nahi hai.

Python isko **set** samajhne ki koshish karta hai.

Problem ye hai ki `report` dictionary aur confusion matrix jaise objects hashable nahi hote.

Correct:

```python
{
    "accuracy": acc,
    "report": report,
    "confusion_matrix": conf_matrics
}
```

Yahan:

```text
key                value
────────────────────────────
"accuracy"         acc
"report"           report
"confusion_matrix" matrix
```
